## Failures and retries

1. **Step-1 driver attempt 1 aborted at the import dialog** (harness defect, not product): `waitForSelector('[data-testid="import-file-input"]')` waited for *visibility*; the picker input is intentionally `class="hidden"` (a file input is never shown; the "Choose files…" button opens it). Fix: wait with `state:"attached"` (Playwright `setInputFiles` targets hidden inputs). Attempt 1 outputs preserved as `m8-step1-ui.out.attempt1` / `m8-step1-backend.log.attempt1`; the isolated temp DB was deleted and the backend restarted (boot 2 at m8-step1-backend.log:19). Rerun: all legs PASS. No product change.
2. **Two stray 401s on identical double-`-F` curl import legs** (`txtbatch:401` at m8-step1-backend.log:62 on project 3, reproduced once at :66 in isolation) while tree GETs and a 413 import with the same cookie jar returned 200/413 seconds apart. Server log :62 shows the middleware 401 (`{"detail":"authentication required"}`). The session cookie is stateless and deterministic (HMAC over the same key — auth.py), the jar was well-formed (single `wa_session` entry, exp ~30 days out verified by decoding the payload), and re-login with the same key made the identical request return the expected 400/200 immediately. Not reproduced after re-login (5 further import legs all green: 400, 413, 409, 404, 201). Classified **harness anomaly** (curl/cookie-jar quirk), no product defect suspected — the behavior under test (400 naming the file, nothing persisted) was proven via both the UI leg and the post-re-login API leg; recorded for transparency, zero impact on the done-gate.
3. **Vite dev-server config location**: the temp proxy config could not resolve `@vitejs/plugin-react` from `/tmp` (vite bundles the config from its own dir). Fix: symlinked `/tmp/opencode/int8s1/node_modules` → `frontend/node_modules` (harness-only). No repo file created or modified.
